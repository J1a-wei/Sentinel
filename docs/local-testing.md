# 本机测试记录

日期：2026-10-21。范围：一期 A 的资产采集、可靠上报和管理界面，具体实现边界见[实现接口约定](implementation-contract.md)。本轮补充真实本机的只读采集与恢复验证；隔离测试继续使用虚构 fixture。

## 本次运行环境

本机为 Ubuntu 22.04，Hub、Scout、PostgreSQL 与 NATS 均以原生进程运行。本次端口与[部署指南](deployment.md)中的 Compose 默认端口不同。

| 服务 | 本次配置 |
| --- | --- |
| Hub UI/API | `http://127.0.0.1:8080` |
| PostgreSQL | 17.11，`127.0.0.1:15432` |
| 真实采集专用数据库 | `sentinel_local_live_20261021` |
| NATS JetStream | `127.0.0.1:14225`，启用传输令牌认证 |
| Scout | 常驻，每 10 秒只读采集本机 |

本轮的 Scout 身份与队列、服务日志、凭证文件存放在已被 Git 忽略的 `var/local-test/`。管理界面登录令牌位于 `var/local-test/admin-token`，凭证文件权限为 `0600`；本文不记录令牌内容或真实资产明细。常驻 Scout 不携带管理令牌。

从仓库根目录查询常驻 Scout 的公开身份与队列状态：

```sh
SENTINEL_STATE_DIR="$PWD/var/local-test/scout" ./target/debug/scout status
```

该命令只读现有状态，不初始化身份、不获取写锁。

## 已知边界

- 本机缺少 `/var/lib/dpkg/arch`，因此主机架构显示未知，并报告覆盖不完整；不以 Scout 的构建架构推断宿主架构。
- 本机无 Docker 守护进程访问权限，本轮未运行容器镜像构建，也未执行 GHCR 推送、OIDC 签名及实际发布验证。
- 本轮没有进行千台压测或长期稳定性验收。漏洞匹配、配置基线、AI、自动升级执行和历史指标聚合仍未接入。

本记录仅保存测试环境说明与汇总结果，不包含凭证、主机名、原始机器标识、软件包/进程/IP 明细。
